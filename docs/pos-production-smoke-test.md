# Hasim Cashier — Production Smoke Test (جهاز Flutter حقيقي)

تاريخ: 2026-09-02  
النطاق: Standalone POS Core فقط. لا Laravel، لا Sync، لا ترخيص، لا كاميرا/Bluetooth.

جهّز: جهاز Android أو Windows/macOS desktop، بناء `apps/hasim_cashier`، وضع الطيران، طابعة شبكة اختيارية، ماسح HID إن وُجد.  
سجّل لكل بند: **Pass / Fail** + ملاحظة + لقطة إن فشل.

نتيجة آخر محاولة تشغيل: [`docs/pos-production-smoke-test-result.md`](pos-production-smoke-test-result.md) — **NOT READY FOR LICENSING** إلى أن يُنفَّذ على جهاز Android حقيقي.

كلمة مرور Backup للتجربة: اختر 6 أحرف على الأقل واحفظها. PIN المدير: 4 أرقام على الأقل.

## Checklist (26)

| # | الخطوة | كيف تنفّذها | Pass؟ |
|---|---|---|---|
| 1 | Install | ثبّت الـ APK/البناء على جهاز نظيف أو امسح بيانات التطبيق. | ☐ |
| 2 | First setup | افتح التطبيق بدون إنترنت. اختر «كاشير محلي مستقل». أدخل اسم المتجر، المدير، المستخدم، PIN. لا يطلب خادماً. | ☐ |
| 3 | Create local user | من الإعدادات/الإدارة أنشئ مستخدم كاشير محلي بـ PIN مختلف إن وُجدت الواجهة؛ وإلا سجّل أن المدير هو المستخدم المحلي الوحيد. | ☐ |
| 4 | Login | اخرج ثم ادخل بـ PIN الصحيح. PIN خاطئ يُرفض. | ☐ |
| 5 | Create product | أنشئ صنفاً: اسم، سعر بهللة (مثلاً 10.50)، باركود، مخزون 10. | ☐ |
| 6 | Barcode lookup | امسح أو اكتب الباركود في الكاشير: يُضاف بالـ `local_id` دون شبكة. باركود مجهول لا يضيف صنفاً فارغاً. | ☐ |
| 7 | Open shift | افتح وردية بنقد افتتاحي معروف (100). محاولة فتح ثانية تُبقي نفس الوردية. | ☐ |
| 8 | Add items | أضف الصنف للسلة (كمية 2 على الأقل). | ☐ |
| 9 | Discount | طبّق خصماً مسموحاً للمدير. الكاشير إن وُجد لا يملك الخصم. | ☐ |
| 10 | Tax | تأكد أن الضريبة تُحسب من إعداد المتجر/الصنف وأن الإجمالي ثابت بعد إعادة الفتح. | ☐ |
| 11 | Cash payment | ادفع نقداً بمبلغ أكبر من الإجمالي. | ☐ |
| 12 | Split payment | بيع جديد: جزء نقد + جزء بطاقة يغطيان الإجمالي تماماً. | ☐ |
| 13 | Change calculation | في الدفع النقدي الأكبر: الباقي = المدفوع − المستحق، وبالهللة الصحيحة (10.50 → لا 10.499). | ☐ |
| 14 | Invoice generation | تظهر فاتورة `INV-000001` (أو بادئة المتجر) مرة واحدة. المخزون ينقص. | ☐ |
| 15 | Print | إن وُجدت طابعة شبكة: اطبع الفاتورة. البيع يبقى ناجحاً سواء طُبعت أم لا. | ☐ |
| 16 | Printer failure | ضع IP خاطئ أو افصل الطابعة ثم أتم بيعاً. البيع والفاتورة ينجحان؛ رسالة الطباعة منفصلة. | ☐ |
| 17 | Return + restock | أرجع كمية أقل من المباعة. المخزون يزيد. إجمالي الفاتورة الأصلية لا يتغير. | ☐ |
| 18 | New sale after return | نفّذ بيعاً جديداً بعد المرتجع. المخزون والحركات متسقة. لا فاتورة مكررة. | ☐ |
| 19 | Close shift | أغلق بنقد فعلي مختلف عن المتوقع. Expected = افتتاح + نقد − مرتجع − صرف. لا إغلاق مكرر ولا ورديتين مفتوحتين. | ☐ |
| 20 | Reports | تقرير اليوم: `invoices_total` / `return_amount` / `net_sales` تطابق المبيعات والمرتجعات. | ☐ |
| 21 | Backup | مدير فقط. أدخل كلمة مرور ≥ 6. الملف الناتج JSON مغلف (لا أسعار/أسماء واضحة داخله). | ☐ |
| 22 | Restore | استعد بنفس كلمة المرور بعد التأكيد. المجاميع والمخزون وأرقام الفواتير تطابق. كلمة مرور خاطئة لا تمسح البيانات. | ☐ |
| 23 | Kill app | Force stop أثناء وجود مسودة في السلة. | ☐ |
| 24 | Restart app | أعد الفتح: التطبيق **لا** يدخل الكاشير تلقائياً. | ☐ |
| 25 | Confirm draft recovery | بعد PIN: المسودة تعود. أكمل البيع. Force stop بعد النجاح: فاتورة واحدة، السلة فارغة. | ☐ |
| 26 | Confirm no network in Standalone | وضع الطيران طوال 2–25. لا رسالة «تعذر الاتصال» تمنع البيع، ولا قائمة انتظار مزامنة إلزامية. | ☐ |

## يفشل السيناريو إذا

- ظهر خطأ API / Dio / Laravel كشرط للبيع أو الدخول المحلي.
- دخل المستخدم بدون PIN بعد إعادة التشغيل أو بعد Logout.
- تكرر رقم فاتورة، أو بقي البيع في السلة بعد النجاح.
- تغيّر إجمالي فاتورة مدفوعة بعد مرتجع.
- Backup غير مشفّر (يظهر `tables` أو أسماء الأصناف في الملف).
- Restore بكلمة مرور خاطئة مسح أو غيّر البيانات الحالية.
- الطابعة الفاشلة اعتُبرت فشل بيع.
